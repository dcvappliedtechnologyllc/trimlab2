# trimlab 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** trimlab 2, a native Mac app that takes a folder of clips, puts them in shoot order on a Reel strip, trims each one on v1's gold-bracket deck, previews the whole Reel gaplessly, and exports one Instagram-ready Reel (one clip in still behaves exactly like v1).

**Architecture:** A SwiftUI app target (the only AppKit code) hosts views from a local Swift package `TrimlabKit` with three libraries. `TrimlabModel` (Foundation only) holds the pure edit list, edits, history, planner and project codec. `TrimlabMedia` (AVFoundation and Core Image) turns a `CompositionPlan` into one `AVMutableComposition` with a custom `ReelCompositor`, which serves both preview (`AVPlayer`) and export (`AVAssetReader` → `AVAssetWriter`). `TrimlabEditor` holds the `@Observable` `EditorModel` and every view, all drawn with custom controls from `Design/`; strip and deck are one `Canvas` each.

**Tech Stack:** Swift 6 language mode with strict concurrency, SwiftUI + Observation, AVFoundation, Core Image on Metal, Swift Testing (+ one XCTest XCUITest target), XcodeGen, `xcodebuild`, Homebrew `ffmpeg-full` (remux shim and ffprobe test oracle only), `rsvg-convert` (logo PDF), self-signed "trimlab dev" code signing.

**Spec:** `SPEC.md` (copy: `docs/superpowers/specs/2026-10-28-trimlab2-design.md`). § references point there. §13 holds the owner's decisions: save next to the clips (Choose… remembered per Reel), batch order = capture date then natural name, side-by-side install as "trimlab 2", crossfade Cut | Short 0.25 s | Long 1 s.

## Global Constraints

- **Never modify camlab or trimlab v1** (`../camlab/`, `../trimlab/`, `../trimlab-native-spike/`). Copy from them, never import across projects, never write into them (§0, §2).
- **No default SwiftUI or AppKit controls in the window:** "no system `Button` look, `Toggle`, `Picker`, `Slider`, `Stepper`, `Menu`, `TextField` chrome, `List`, `Form`, scroll indicators, `.help()` tooltips, `.alert`, `.confirmationDialog`, `.sheet`, `AVPlayerView` or `VideoPlayer`." Every control comes from `TrimlabEditor/Design`. The only system UI allowed: the menu bar and the Open and Choose Folder panels (§6.0).
- **"Gold `#C9A86A` is the only accent; DCV cyan only in the DCV logo's rule."** Colours come only from `Design/Tokens.swift` (§6.1).
- Inter for all UI text with `monospacedDigit()` on every number; Bodoni Moda only for the CTC wordmark, "Drop clips." and "Saved." No system font ever visible (§6.1, §6.2).
- **Offline at runtime:** no network at runtime, fonts bundled (§10).
- **No ffmpeg in the export path.** ffmpeg is used **only** for remuxing `.mkv`/`.avi` to `.mov` in the cache (`-c copy`) and `ffprobe` as the test oracle (§2). Every `Process` call is an argv array, never a shell string, and is logged.
- **AppKit only in the app target.** `TrimlabModel`, `TrimlabMedia` and `TrimlabEditor` never `import AppKit`/`UIKit` or use `NSView`, `NSImage`, `NSColor`, `NSWorkspace` (§3.1, `test_no_appkit_in_package`).
- **Bundle id `com.dcv.trimlab2`**, `CFBundleName`/display name "trimlab 2", file `trimlab2.app`; prefs `UserDefaults` suite `com.dcv.trimlab2`; logs `~/Library/Logs/trimlab 2/`; cache `~/Library/Caches/trimlab 2/`; `os.Logger` subsystem `com.dcv.trimlab2` (§2, §8.4, §13.3).
- **Never overwrite a source clip** (or the project file). The writer goes to `<dest>.partial.mp4` and renames on success (§4.9, §5.5).
- **Don't rebuild or overwrite `dist/trimlab2.app` while it is running.** `App/build.sh` refuses if `pgrep -f trimlab2.App/Contents/MacOS/` matches. Quit it first.
- Sandbox off, hardened runtime off, no entitlements beyond the defaults (§2). The builder never runs `sudo` (§0).
- Swift 6 language mode, strict concurrency; `xcodebuild` only; the Xcode project is generated from `project.yml` and `trimlab.xcodeproj` is git-ignored (§0).
- Tests: Swift Testing (`import Testing`), plus XCTest only in `UITests/`. Media tests **fail, not skip**, without ffprobe or fixtures (§11.1). No test reads `~/Downloads/Spa Tour/`.
- TDD is mandatory for `TrimlabModel` and `TrimlabMedia` (and the `EditorModel` intents in this plan): write the test, watch it fail, then implement (§0).
- Window 1240×860 at first, minimum 900×720, background `--bg-0` (`#0B0C0E`) before the first frame (§4.11, §6.0).
- Commits go on `feat/v2`. Every commit message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A big drop with a bad file in it** (40 clips, one truncated `.MOV`, a stray `.jpg`, a `.txt`). Expected: 39 tiles in capture order, one quiet note ("Skipped 1 file trimlab can't open." for the `.txt`/`.jpg`, plus "Can't open IMG_0007.MOV. trimlab can't play this kind of file." for the corrupt one), no tile left shimmering, and one undo removes the whole batch. Tests: Task 18 `truncatedMovThrowsUnplayable`, Task 26 `importBatchWithOneCorruptFile`.
2. **A source that disappears after it was found** (file deleted or drive ejected between sessions, or mid-export). Expected: on reopen a "Missing" tile, preview plays without it, Export blocked with the §4.9 line and autosave keeps the clip; mid-export a `sourceUnreadable` error ("A clip can't be read any more. Check that its drive is connected.") with the partial deleted. Tests: Task 23 `sourceRemovedDuringExportFailsAndDeletesPartial`, Task 31 `reopenWithDeletedSourceMarksMissingAndBlocksExport`.
3. **A clip shorter than the 0.5 s minimum span** (an accidental tap-record, 0.4 s). Expected: it imports and plays as one 0.4 s tile, its handles can't move (span rule is `min(0.5 s, duration)`), split refuses with the edge note, and a crossfade next to it is cut to 0.2 s. Tests: Task 10 `tinyClipHandlesCannotMove`, Task 11 `splitTinyClipRefused`, Task 12 `crossfadeNextToTinyClipIsHalfItsLength`.
4. **The Reel crossing 3:00 while trimming** (a handle drag that moves the total from 2:59.9 to 3:00.2). Expected: exactly 180 s is not over; one frame past is; the "Trim … more" figure rounds **up** to 0.1 s so it never reads "Trim 0:00.0 more"; the strip marker and dimmed tiles follow the live (uncommitted) drag. Tests: Task 12 `overLimitBoundary`, `trimMoreRoundsUp`; Task 28 `limitMarkerFollowsDraftTrim`.
5. **A VFR clip crossfading into a 60 fps clip** in a 29.97 Reel. Expected: Reel rate stays 29.97 (most Reel time), CFR frame count exact, the overlap blends both, no composited frame delta > 1 frame at the join, and the VFR tail's 100 ms frames are duplicated on the grid, never reported as a join gap. Test: Task 22 `crossfadeVFRIntoSixtyIsCFRAndGapless`.

The newer-schema refusal is spec-tested (§11.2); its follow-on, autosave never overwriting a refused file, is pinned in Task 31 `refusedProjectIsNeverAutosaved`.
