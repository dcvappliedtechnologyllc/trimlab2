- Task 40 (launch sweep): a user's own file named exactly `<stem>.<8 lowercase hex>.partial.<ext>` or `<stem>.<8 lowercase hex>.replacing.<ext>`, at least a day old, in a folder trimlab exported to (`lastFolder`) or the open Reel's export folder, would be deleted at launch as an export temporary. Accepted as very unlikely; only regular files, no links, folders or subfolders, each removal logged — cost if wrong: one such user file lost
- Review fix M-2 (launch sweep, `.sb-`): the same exact-pattern, regular-file, no-link, day-old, one-folder-level rules now also cover `<partial>.sb-<letters, digits, hyphens>`, the writer's network-use temporary beside a partial. No new risk class: the name still has to carry trimlab's `<8 hex>.partial.<ext>` tag first.
- Final review I-2 (inline Reel rename, §6.1, built before the v2 merge): click the header's Reel name, or Return/Space while it has keyboard focus, to edit it in a field; Return, focus leaving or a press on the strip/deck/stage commits, Esc cancels. Empty, whitespace-only, or unchanged after trimming does nothing; the name is sanitised with the export file name's `Naming.sanitized`. One undo step, restored with the selection; nothing while an export runs or a modal is open. A one-clip Reel shows its clip's file name and isn't renameable. Accessibility label "Reel name", identifier `reel.name` — cost if wrong: none (UI behaviour)
- Final review I-2 (the file): with a file, `<old>.trimlab` is renamed to `<new>.trimlab` in the same folder through the write chain (`renamex_np` with `RENAME_EXCL`, off the main actor); saves asked for during the rename wait for it. A taken name (any file, folder or link, any case, or a file a save was refused at) is refused: the name stays, nothing is recorded, quiet note "A Reel named “X” is already in this folder." Without a file yet only the name changes, and the first file is then `<Reel name>.trimlab` (then ` 2`) instead of the folder name. Undo/redo move the file back and forth by the same rules; if the old name was taken meanwhile the file stays put, the name still changes, and the log says so. Open Recent follows the renamed file; the default export name follows the Reel name. Never overwrites, never touches clips — cost if wrong: a Reel file named differently from what the owner expects (never data loss)
- Final review I-2, round 2 (coordinator): a typed trailing ".trimlab" (any case) is dropped before sanitising. Return or Esc in the rename field hands keyboard focus back to the name with its ring; a pointer close (click-away, a press on the strip/deck/stage) leaves no focus and no ring, as `pointerPressed` does. ⌘E while a committed rename's file move is in flight opens the export sheet once the move lands, so the sheet shows the final name and the rename is always an undo step (chosen over refusing the rename: the move takes milliseconds, and a refusal would drop a name the owner already confirmed) — cost if wrong: none (UI timing)
- Rename review fixes (rename-review.md): a name still being typed is committed (as a click-away) by ⌘E, `?`, New Reel, open, quit and window close; a field whose rename becomes impossible otherwise (another modal, under two clips) ends with the name unchanged. A move that lands under a modal (the key map) moves the file and updates Open Recent at once, but the name change and its undo step wait for the modal to close (nothing is recorded under a modal, §4.8). The ⌘E wait is one at a time, stands down if a modal opened or the Reel changed, and New Reel/open cancel it. The move works out its file when it runs and moves it only if it holds this Reel; another Reel's file is left alone and the next save writes the new name. Volumes without `RENAME_EXCL` (exFAT, some shares) use an `O_EXCL` placeholder then a plain rename. Return/Esc pass to an input method while it composes. A name that sanitises to nothing ("...") is nothing typed. Open Recent drops the old path and adds the new one, open or closed Reel — cost if wrong: none (UI timing, never data loss)
- Task 42 (build, Apple silicon only): trimlab 2 is built for arm64 only. SPEC §2 and §9 are silent, but §4.6 stores peaks as `Float16`, which doesn't exist on x86_64 macOS, so a Release build that also compiled x86_64 failed. `project.yml` sets `ARCHS: arm64`, and `App/build.sh` passes `ARCHS=arm64` on the xcodebuild line because the TrimlabKit package targets don't inherit the project's ARCHS (without it build.sh failed too). A plain `xcodebuild -configuration Release -destination 'platform=macOS'` still needs `ARCHS=arm64` — cost if wrong: no Intel Mac build (none is used)
- Task 42 (Step 2, grep 3): the URL grep hits the two bundled font licences, `Resources/Fonts/OFL-BodoniModa.txt` and `Resources/Fonts/OFL-Inter.txt` (their project and licence URLs, text shipped with the fonts, not network code). These hits are expected. Run grep 3 as `grep -rnE "https?://" App Packages/TrimlabKit/Sources Resources | grep -v "www.apple.com/DTDs" | grep -v OFL-`, which prints nothing — cost if wrong: none
- Task 42 (launch while quitting): `open -a trimlab2.app --args -TLOpen …` sent while the previous copy is still quitting opens nothing: Launch Services sees the app as running, so `open` activates that copy instead of starting a new one, and `--args` only ever reach a new process (reproduced: `open` returned 0, no new process started, the old one finished quitting). Our quit path never sees the clips, so there is nothing to keep. Accepted edge: wait for the old process to exit before launching with `-TLOpen` (Finder, Dock and Open With are unaffected) — cost if wrong: a bench launch comes up without its clips
